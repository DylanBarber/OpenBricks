# OpenBricks 0.5.0

OpenBricks 0.5 brings run diagnostics, shared dashboards, dataset health and
collaboration to the self-hosted workspace, with encrypted notebook secrets and
optional single sign-on. The default deployment remains management and compute,
with 1 GB and 4 GB Docker ceilings. Compute defaults to a configurable two-CPU
quota that keeps JVM background pools sized for the assigned capacity.

## Inspect runs and share data

The run profiler records bounded Python/JVM/container memory and CPU timelines,
Spark jobs/stages, input/output, shuffle/spill metrics and query plans. Compare
two captured runs without executing them again. Missing metrics are explicitly
unavailable. Profiles follow output retention and known-secret redaction.

Saved-query dashboards add persistent tile layouts, typed filters and scheduled
refreshes. Viewers read cached snapshots; viewing a dashboard does not start
compute. Failed refreshes preserve the last successful snapshot with visible
failure/staleness information. Asset pages combine recorded quality history,
owners, freshness thresholds and bounded upstream/downstream lineage graphs.
Lineage represents recorded read/write observations, including failed runs; it
does not certify an external transaction or automatically capture every I/O call.

## Collaborate and manage secrets

Notebook collaboration includes presence, threaded discussion and review requests
pinned to source hashes. Source changes make prior reviews stale. Live mode
lets teammates edit different cells simultaneously through short-lived exclusive
cell leases, autosave and stale-source checks. Disable live mode after finishing
edits before changing cell structure, importing replacement source or moving a
notebook. Reviews are advisory and do not replace project permissions.

Notebook secret scopes store write-only values encrypted with the workspace's
existing encryption key. Select named keys explicitly per notebook and read them
using `dbutils.secrets.get(scope, key)` or `notebook_secrets.get(scope, key)`.
Current permissions and values are resolved at dispatch; secret plaintext is not
part of notebook source, environment manifests or saved run envelopes. Captured
output, errors, tables, profiles and native worker stderr mask known values,
including rotated values retained by an interactive worker. This remains a
trusted-code environment: intentional encoding, file writes or network transfers
are not prevented by output masking. Moving a notebook clears its secret aliases.

Optional OIDC login uses authorization code, PKCE, one-use state/nonce and
verified ID tokens. Identity is bound to issuer and subject, without email-based
account linking. Configured groups map to project roles; local administrator
login remains independent. A paginated audit console and bounded CSV export
expose existing project action history to owners and administrators.

## Concurrency and deployment

The default Hive mode preserves the existing local metastore and single-owner
Spark lease. Explicit Unity Catalog mode disables the embedded Hive/Derby
metastore and permits independent Spark workers under the existing resource
budgets. Configure and validate the shared catalog and storage before switching;
this does not convert local Hive metadata or guarantee safe concurrent writes
for every external storage system. See [compute configuration](https://github.com/DylanBarber/OpenBricks/blob/main/docs/COMPUTE_PROFILING.md).

Finish active work, create a verified encrypted backup, preserve its encryption
key and configuration, and use matching 0.5.0 management/compute images. New
metadata remains in the existing persistent volume. See [identity and secrets](https://github.com/DylanBarber/OpenBricks/blob/main/docs/IDENTITY_AND_SECRETS.md),
[dashboards and assets](https://github.com/DylanBarber/OpenBricks/blob/main/docs/DASHBOARDS_AND_ASSETS.md)
and [deployment](https://github.com/DylanBarber/OpenBricks/blob/main/DEPLOYMENT.md).

## Release verification

Publication is gated on the backend suite, a real Microsoft SQL Server
integration suite, the production web build, CLI packaging, and the full
disposable system smoke test. The system gate additionally runs real Spark
profiling and concurrent catalog execution, Chromium UI tests for dashboards,
assets, secrets, coediting, reviews, audit export and real OIDC redirects, and
encrypted fresh-host restoration of the new metadata and selected secrets.
Generated credentials, browser traces and recovery receipts remain private.
