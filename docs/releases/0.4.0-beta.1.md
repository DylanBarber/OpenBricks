# OpenBricks 0.4.0-beta.1

This beta adds resource-aware workers, Git authoring, repeatable automation, deployable projects, SQL Server synchronization, off-host recovery, and lightweight SQL.

- Independent interactive sessions by project/user/notebook/environment; fresh job workers; configurable compute/project budgets and queue priorities.
- Repository file editing, branches, diffs, notebook export, explicit commits/pushes, GitHub pull requests, and version-checked import conflict review.
- Date-range backfills with captured sources, bounded missed-schedule recovery, and file-arrival, Delta-log, and upstream-workflow triggers.
- Declarative project bundles with validate/plan/deploy/promote, a portable Python CLI wheel, and scoped expiring service-account tokens.
- SQL Server Change Tracking synchronization of inserts, updates, and deletes into owned Delta sinks, with schema/source/checkpoint validation and a pinned real-server test harness.
- Scheduled encrypted S3 backups, failure alerts, isolated restore drills, selected S3/catalog exports, direct remote archive restore, and explicit additive recovery plans.
- DuckDB queries for local or selected S3 CSV, JSON, and Parquet files without Spark startup.

Management and compute retain their default 1 GB and 4 GB Docker ceilings. Worker budgets use a process-tree memory monitor; they do not create separate security containers. Local Hive-backed Spark work retains a single-owner lease. OpenBricks remains intended for trusted teams.

Change Tracking requires source configuration and a new dedicated sink. Delta triggers observe transaction-log commits; they are not general database CDC subscriptions. Backups cover local data and selected exports, not every external service. External writers should be quiescent for coordinated recovery.

Before upgrading, finish active work, preserve configuration and encryption keys, and create a validated backup. Use matching management/compute images. Keep the prior images and backup for rollback. See [deployment](https://github.com/DylanBarber/OpenBricks/blob/main/DEPLOYMENT.md), [automation](https://github.com/DylanBarber/OpenBricks/blob/main/docs/AUTOMATION.md), and [operations](https://github.com/DylanBarber/OpenBricks/blob/main/docs/OPERATIONS.md).

Published assets include pinned Linux amd64 images, portable Docker archives with SHA-256 files, deployment configuration, and the OpenBricks CLI wheel. Runtime images are not substitutes for persistent data backups.
