# OpenBricks 0.4.0

OpenBricks 0.4.0 is the first stable release of the self-hosted notebook and data workspace. Run Python, Spark SQL, and DuckDB; organize notebooks in folders; build reusable wheels; schedule pipelines; and connect independent compute services using matching Docker images.

This release includes the 0.4 beta features: isolated notebook worker processes and budgets, Git authoring and guarded imports, date backfills and event triggers, deployable project bundles and a CLI, SQL Server Change Tracking into Delta, and encrypted off-host backups with fresh-host recovery.

## Fixes from expanded integration testing

- SQL Server inserts preserve high-precision decimal values, Unicode, and nulls without the driver's fast-batch buffer truncation. A failed batch rolls back its transaction.
- Native SQL Server queries preserve `datetimeoffset` offsets and seven fractional digits, including `time(7)`. Change Tracking stores SQL `time` values as exact text supported by Spark. Timestamp keys finer than Spark's microsecond precision are rejected before synchronization.
- Concurrent workers safely reuse a completely published, matching wheel environment.
- Remote restore reserves workspace maintenance before downloading and cannot clear another backup's pause.
- Interrupted local backups become failed records on restart while their artifact bytes remain available; offsite backup recovery stays retryable.

## Validation and reproducibility

The disposable system harness uses a real Microsoft SQL Server Developer instance, separate restricted database accounts, independent compute volumes, SeaweedFS, Unity Catalog OSS, and local SMTP/webhook receivers. It exercises the management API through the web proxy, real Python/Spark workers, SQL reads and writes, transactional failures, Change Tracking replay and failure recovery, permissions, workflows, scheduling, pagination, package distribution, resource limits, and encrypted backup/recovery.

The release workflow gates publication on the backend and live SQL suites, a production web build, CLI packaging, and the whole-system smoke test. See [the reproducible test guide](https://github.com/DylanBarber/OpenBricks/blob/main/docs/STABLE_TESTING.md) for commands and coverage. Public tests contain synthetic data; credentials and receipts remain local.

## Upgrade and deployment

Management and compute retain default Docker ceilings of 1 GB and 4 GB. Use the same version and build identity on all compute hosts. Finish active work, create a validated encrypted backup, preserve configuration and encryption keys, and retain the previous images for rollback before upgrading. Notebook reruns that capture an older runtime identity require that matching runtime.

Published assets include Linux amd64 images, portable Docker archives with SHA-256 files, deployment configuration, documentation, examples, and an installable CLI wheel. See [installation](https://github.com/DylanBarber/OpenBricks/blob/main/docs/RELEASING.md) and [deployment](https://github.com/DylanBarber/OpenBricks/blob/main/DEPLOYMENT.md).

OpenBricks is intended for trusted teams. Worker processes share their compute container's filesystem and account. Local Hive-backed Spark workers use a single-owner lease. Backups cover local data and explicitly selected exports; quiesce external writers for coordinated recovery. Spark timestamps use microsecond precision. This release does not make arbitrary external systems part of a notebook's captured execution snapshot.
